# Write useful content without generic AI copy

Use this for new copy, refreshes and authorized rewrites. Pair it with the
editorial reference. An audit alone does not require a replacement article.

## Prepare a brief from evidence

Use the content brief template. Establish audience, reader task, actual offer,
intent cluster, existing/proposed URL, desired action, brand voice and constraints.
Read existing material and supplied facts before drafting. For an SEO research
request inspect current intent and competing pages; in no-browse/local-only
mode label query choices provisional and continue from supplied evidence.

Create a claim ledger with claim, source, status, time sensitivity and treatment.
Separate confirmed facts, business self-reports, proposals, conflicts and unknowns.
Keep “planned”, “subject to”, exclusions, dates and price bases attached to the
claim they qualify. Never turn an aspiration into an available service.

Identify the original value the piece will add. It can be a clearer explanation,
documented process, supported comparison, worked example or actual experience.
If there is insufficient information for essential copy, draft the supported
sections and list missing inputs separately. Do not fill the gaps with invented
projects, reviews, outcomes, awards, expertise or plausible commercial terms.

## Structure around the reader's job

Choose the page structure from intent rather than a fixed landing-page formula:

| Page type | Useful progression, adapted to the actual task |
| --- | --- |
| Service/local page | What is offered and where; fit; scope/process; evidence; verified terms; next action |
| Product/category | Product purpose or selection criteria; meaningful specs/options; availability and terms; comparison/navigation; action |
| Guide/tutorial | Direct answer; prerequisites; working steps/examples; failure cases; limits; relevant next steps |
| Comparison | Comparable alternatives; explicit evaluation method; sourced dimensions; tradeoffs; who each fits |
| Explainer | Definition in context; mechanism; concrete example; limits/misconceptions; sources and related tasks |

Do not copy the dominant competitor's outline. Use headings that describe useful
content, not repeated exact-match keywords. A section earns its place by answering
a question or helping a decision. Tables require genuinely comparable dimensions;
FAQs require real unanswered questions. Preserve enough context for an excerpt
to stay accurate, including subject, units and qualifications.

## Draft and edit

1. Lead with the answer or actual offer. Use verified specifics before adjectives.
2. Explain with named subjects, precise verbs and useful examples. Define terms
   when the audience needs it; do not strip domain meaning to force simplicity.
3. Use primary evidence for technical claims and current authoritative sources
   for consequential factual guidance. Date time-sensitive comparisons. Place
   citations near claims; self-reported competitor claims remain self-reported.
4. Integrate the primary query and natural variants where they clarify meaning.
   No keyword density, word-count target, required transition vocabulary or
   arbitrary formula for answer length.
5. Run the anti-slop pass: remove empty introductions, hype, duplicated ideas,
   manufactured contrasts and template cadence. Replace vagueness only with
   supported specifics. Keep authentic voice and meaningful exceptions.
6. Read as the intended user. Check sequence, unresolved objections, distracting
   jargon, inaccurate implications and the actual CTA destination.

Do not claim firsthand testing, interviews, lived experience or authorship that
did not occur. Fictional examples must be clearly labeled as illustrative, and
must not become proof about the business. Do not add deliberate mistakes or use
AI detectors as an editorial objective. Handle multilingual copy in its language
and cultural context; English cliche lists are review prompts, not translation rules.

## Metadata, links and layout handoff

Deliver an accurate title, useful description and clear H1 alongside the body.
Character counts can be an editorial display check or a site's own requirement,
not a universal ranking limit. Search engines may choose different title/snippet
text. Preserve existing URLs unless a migration is in scope.
[Title links](https://developers.google.com/search/docs/appearance/title-link),
[snippets](https://developers.google.com/search/docs/appearance/snippet).

Propose internal links as source section, descriptive anchor, real destination
and reader purpose. Verify destination availability when possible; label proposed
URLs as proposed. Avoid stuffing anchors or linking every keyword occurrence.
Suggest images only when they teach, demonstrate or help a decision; give purpose
and honest alt-text guidance, never fabricated business photos or review proof.

For a layout handoff specify section purpose, facts needed, appropriate component,
mobile behavior and accessible semantics. Put implementation notes outside the
publishable copy. Recommend schema only after matching visible facts and current
feature eligibility; do not make a draft depend on invented structured data.

## Delivery and acceptance

Separate the final copy from research, evidence requests and publisher notes.
Preserve Markdown frontmatter, code examples, legal/commercial meaning and the
user's requested format. Use a sibling draft or reviewed diff when authorized;
never silently overwrite the source to make the audit look complete.

Acceptance: the intended task is answered; each material claim is supported;
important qualifications survive; no generic section repeats another; title and
CTA match the page; natural language fits the brand; links have a purpose; and
unresolved facts are visible outside the copy. Show a brief before/after example
explaining the substantive improvement, not just a list of replaced words.

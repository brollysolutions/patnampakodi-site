# Audit existing content before replacing it

Read the supplied material completely. Record the version, URL/file and whether
it is a whole page, fragment, draft, rendered page or export. A prose-only audit
can establish editorial problems; it cannot establish production indexability,
responsive behavior or Core Web Vitals.

## Inventory and coverage

For a site, combine the authorized route/CMS inventory, sitemap, internal links
and search landing pages. Record each source's limitations: a sitemap can omit
pages, crawling can miss orphans, and analytics can omit pages without traffic.
Group by page type, intent, business role, language and shared template.

Include important commercial pages, search landing pages, declining pages,
recently changed pages and representatives of each relevant template. State
sample size and selection; do not claim sitewide coverage from the homepage.
An orphan claim requires an adequate internal-link inventory; otherwise it is
a candidate orphan within the inspected sample.

Inventory fields: URL, source/version, page type, intended audience/task, primary
cluster, title/H1, material update date, current content owner if known, observed
index evidence, links, performance window, business value and review coverage.
Do not convert an unknown update date into evidence of stale content.

## Review page and section quality

| Dimension | Questions that change the recommendation |
| --- | --- |
| Intent fit | Does this format answer what the reader came for? Is the real answer delayed or absent? |
| Completeness | Are essential steps, prerequisites, exclusions, criteria or next actions missing? |
| Accuracy | Are facts current, internally consistent, sourced and qualified? Do links support the actual claim? |
| Original contribution | Is there useful experience, a demonstration, analysis, example or explanation beyond paraphrasing sources? |
| Trust | Are the business, author/reviewer when relevant, terms and evidence identifiable without fabricated credentials? |
| Specificity | Could a reader distinguish the offer from a competitor after replacing the logo? |
| Readability | Does each section help the task, preserve technical meaning and use natural audience language? |
| Structure | Do title, H1, headings, snippet copy, tables and links agree on the page's purpose? |
| Decision usefulness | Can the reader assess fit, limits, alternatives and the next step honestly? |
| Retrieval | Are key facts readable as text and understandable when a passage is quoted separately? |

Use the editorial reference for the anti-slop pass. Flag exact paragraphs,
headings, claim spans or source lines, with a short example and an actionable
change. “Improve E-E-A-T” is insufficient: name the missing evidence and its
reader impact. Do not invent an E-E-A-T score used by Google.

## Optional editorial rubric

When comparison or a scorecard helps, rate the relevant dimensions above:
**0** = observed material failure; **1** = major gaps; **2** = useful with specific
gaps; **3** = strong on inspected evidence; **U** = unverified; **N/A** = irrelevant.
Attach an evidence-based reason to every rating. Report the profile and assessed
coverage, not an aggregate masquerading as a ranking or authorship probability.
An unknown production check is U, never a zero or a pass. A major false claim
stays a priority even if every stylistic dimension looks good.

## Diagnose decay and overlap

Compare consistent query/page/country/device/search-type windows; use matching
seasonal periods when relevant. Record data lag, low sample sizes, URL moves,
campaigns and known site changes. Separate:

- Falling demand from loss of visibility for the same queries.
- Impression changes from CTR changes and new query coverage.
- Tracking changes from real changes in visits or qualified conversions.
- Intent/SERP changes from content defects and technical access failures.

Form competing hypotheses and identify a check that distinguishes them. A
traffic decline alone does not prove an algorithm penalty or a need to rewrite.
Without analytics, decay is unverified; still audit the actual content.

## Recommend a disposition

| Disposition | Evidence needed | Safeguard |
| --- | --- | --- |
| Keep | Accurate, distinct, useful content serving a real task | Preserve useful passages and established URLs |
| Refresh | Specific outdated facts, omissions or usability problems | Identify exact changes and recheck cited/commercial facts |
| Consolidate proposal | Same intent, overlapping value and a reason one page would serve users better | Preserve unique content, relevant destinations, links and existing query value |
| Split proposal | Multiple distinct tasks need different formats or journeys | Define separate value and URL ownership before creating pages |
| Retire proposal | Obsolete/incorrect content with no continuing task or appropriate replacement | Review history, links, contractual/legal needs and traffic before any deletion/noindex/redirect |
| Investigate | Missing or conflicting evidence prevents a sound choice | State the smallest missing check rather than guessing |

Low word count, low traffic or keyword overlap alone does not justify deletion.
Audit-only scope produces proposals. Noindex, canonical changes, redirects,
removals and mass rewrites require implementation scope; do not silently enact
them. An established accurate page may need only a small correction.

## Output

Provide page inventory, section findings, claim ledger, rubric when useful,
disposition rationale, related-URL conflicts and a prioritized action backlog.
Preserve business facts in short illustrative edits. Include a full replacement
draft only when requested; use the content-writing procedure for that handoff.
